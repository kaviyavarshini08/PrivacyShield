# PrivacyShield Disaster Recovery & Rollback Manual

This manual provides production instructions for rollback procedures, Point-in-Time Recovery (PITR) of PostgreSQL databases, Docker container service recovery, and Kubernetes deployments rollbacks.

---

## 1. Database Restoration & Recovery

### Daily Backups Restoration
In the event of database corruption or hardware failures, restore from daily binary dumps generated by the daily pg backup script:
```bash
# 1. Stop all application workers to terminate active connection pools
sudo systemctl stop privacyshield-backend privacyshield-worker

# 2. Restore database dump using pg_restore
pg_restore -U dbadmin -d privacyshield -h localhost --clean --if-exists /var/backups/postgres/privacyshield_daily_latest.dump

# 3. Restart application workers
sudo systemctl start privacyshield-backend privacyshield-worker
```

### Point-in-Time Recovery (PITR)
If a critical query error corrupted tenant records at a specific hour:
1. Stop PostgreSQL server:
   ```bash
   sudo systemctl stop postgresql
   ```
2. Restore the latest base backup files from storage vault.
3. Configure `recovery.signal` file in the Postgres data directory:
   ```bash
   touch /var/lib/postgresql/data/recovery.signal
   ```
4. Define target recovery timestamp in `/var/lib/postgresql/data/postgresql.conf`:
   ```ini
   restore_command = 'cp /var/lib/postgresql/pg_wal/%f "%p"'
   recovery_target_time = '2026-05-28 10:15:00 UTC'
   ```
5. Restart PostgreSQL server and observe logs as it rolls WAL forwards:
   ```bash
   sudo systemctl start postgresql
   ```

## 2. Docker Compose Rollback Guidelines

If the newly deployed container image introduces runtime bugs:
1. Revert container image tags in `docker-compose.yml` to the last known stable build.
2. Force recreate services:
   ```bash
   docker-compose down
   docker-compose up -d --build --force-recreate
   ```
3. Prune dangling resources to free disk spaces:
   ```bash
   docker system prune -f
   ```

## 3. Kubernetes Rollback Guidelines

To roll back a rolling update deployment immediately:
1. View deployment revision history:
   ```bash
   kubectl rollout history deployment/privacyshield-api -n privacyshield
   ```
2. Rollback to the previous stable revision:
   ```bash
   kubectl rollout undo deployment/privacyshield-api -n privacyshield
   ```
3. To roll back to a specific revision ID (e.g. Revision 3):
   ```bash
   kubectl rollout undo deployment/privacyshield-api --to-revision=3 -n privacyshield
   ```
4. Monitor pod health and readiness checks:
   ```bash
   kubectl rollout status deployment/privacyshield-api -n privacyshield
   ```

## 4. Post-Recovery Verification Checklist

Once a rollback or restore completes, verify the following:
- [ ] Query `/health/readiness` and ensure it responds with `HTTP 200 OK` (verifying Postgres and Redis connections).
- [ ] Check Celery active queue metrics to ensure tasks continue processing.
- [ ] Run a test document upload to verify OCR OCR preprocessing and Presidio scanning engines.
